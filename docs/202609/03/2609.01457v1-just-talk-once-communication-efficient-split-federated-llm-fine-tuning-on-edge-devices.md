## 摘要
大语言模型（LLM）的微调正日益转向边缘设备上生成的数据，而内存、计算、带宽和连接性限制使得传统的联邦学习难以维持。拆分联邦微调（SFT）通过将大部分模型参数和计算卸载到服务器来提高客户端效率，但需要跨拆分接口的逐步双向通信循环，并迫使客户端在整个训练过程中持续参与。在本文中，我们提出了L形SFT，一种消除了这一双向瓶颈的拆分微调框架。我们的关键洞见是，现代LLM中的权重绑定使得服务器端的隐藏激活可以直接通过目标嵌入进行监督，从而可以在服务器上计算训练损失，而无需将服务器输出返回给客户端。为了进一步消除对持续客户端参与的需求，基于L形SFT，我们引入了一次性SFT，其中客户端仅上传一次激活然后离线，而服务器继续对缓存的表示进行优化。我们在一个包含异构边缘客户端（包括商用智能手机和NVIDIA开发者板）的真实系统测试台上实现了我们的设计。实验表明，与现有的SFT基线相比，我们的方案显著降低了通信成本和客户端在线时间。

## Abstract
Large language model (LLM) fine-tuning is increasingly shifting toward data generated on edge devices, where memory, computation, bandwidth, and connectivity constraints make conventional federated learning difficult to sustain. Split federated fine-tuning (SFT) improves client-side efficiency by offloading most model parameters and computation to the server but requires step-by-step bidirectional communication loop across the split interface and forces continuous client involvement throughout training. In this paper, we present L-shaped SFT, a split fine-tuning framework that removes this bidirectional bottleneck. Our key insight is that weight tying in modern LLMs enables server-side hidden activations to be directly supervised using target embeddings, allowing the training loss to be computed on the server without returning server outputs to the client. To further eliminate the need for continuous client participation, based on L-shaped SFT, we introduce one-shot SFT, in which clients upload activations once and then go offline while the server continues optimization over cached representations. We implement our design in a real system testbed with heterogeneous edge clients, including commercial smartphones and NVIDIA developer boards. Experiments demonstrate that our schemes significantly reduce communication costs and client online time compared with existing SFT baselines.

## 1. 核心问题与研究动机

- **背景**：随着公开数据集预计在 2026–2032 年间枯竭，LLM 微调的重心正转向利用边缘设备上产生的海量数据。然而，直接采集这些数据用于集中式微调，在金融、医疗等敏感领域面临所有权、部署与合规方面的约束。
- **传统联邦学习的瓶颈**：在资源受限的边缘设备上直接进行全模型联邦微调存在三大挑战：
  - **内存瓶颈**：FP16 训练每 1B 参数约需 16GB RAM；NVIDIA Jetson Orin Nano 仅 4GB、华为 nova 9 Pro 仅 8GB，运行完整 LLM 极易内存溢出。
  - **计算瓶颈**：边缘设备缺乏高效全模型训练所需的处理能力。
  - **通信瓶颈**：反复上传全模型更新需要消耗大量无线带宽。
- **现有 SFT 方案的问题**：
  - 标准 SFT（Split Federated Fine-tuning）将大部分参数与计算卸载至服务器，但自回归 LLM 微调中损失计算需要在目标 token 处进行——若将目标 token 上传服务器则泄露隐私。
  - 为解决上述问题，U-shaped SFT（如 EUSFL、MPSL、FlexP-SFL、MobiLLM）将预测头与损失计算移回客户端，但引入了**每步双向通信循环**（激活上传→激活下载→梯度上传→梯度下载），使通信成本翻倍，并强制客户端**持续在线参与**——这在带宽不稳定、连接间歇性的移动环境中不切实际。
- **研究问题**：
  - RQ1: 如何重构 U-shaped SFT 流水线以降低每步通信开销，同时不牺牲微调有效性？
  - RQ2: 如何放宽对连续客户端-服务器同步的需求，从而减少客户端在线时间？

## 2. 方法论

### 2.1 L-shaped SFT：消除双向瓶颈的框架

- **核心洞察**：现代 LLM 普遍采用**权重绑定（weight tying）**——输出头权重矩阵等于输入嵌入矩阵的转置（$$W_{head} = E^{\top}$$）。经过预训练的嵌入空间具有强语义一致性：若隐藏状态与正确 token 的嵌入对齐良好，绑定的输出头会给该 token 最高分。作者实证验证了嵌入的“自恢复率”：GPT-2 与 Llama-3.2 的 Top-1 恢复率超过 99.5%，Qwen2.5 也高于 94%。
- **关键设计**：将监督信号从客户端转移到服务器端——用**目标嵌入**直接监督**服务器端隐藏激活**，而非通过客户端的预测头进行 token 级监督。客户端只需上传 `(cut-layer 激活, 目标嵌入)`，无需接收服务器输出、也无需回传梯度。

### 2.2 激活空间目标（LA-Loss）

- 传统交叉熵在服务器端不可行（因为无法访问完整词汇投影），作者定义了一种对比式激活空间损失：

$$L_{A\text{-Loss}} = -\log \frac{\exp(s_y / \tau)}{\exp(s_y / \tau) + \sum_{e_k \in \mathcal{Q}} \exp(s_k / \tau)}$$

其中 $s_k = \text{sim}(h_s, e_k)$，$\mathcal{Q}$ 为服务器端历史缓存（存储目标嵌入作为负样本代理），$\tau$ 为温度超参数。该损失将预测隐藏状态拉向目标嵌入，同时推开缓存中的其他嵌入。

### 2.3 理论分析

- **定理 1（梯度一致性）**：当满足三个条件——(i) $\tau = 1$；(ii) 历史缓存覆盖全词汇表 $\mathcal{Q} = \{1, \ldots, V\}$；(iii) 权重绑定成立——则 $\nabla_{h_s} L_{A\text{-Loss}} = \nabla_{h_s} L_{CE}$，即 A-Loss 产生与标准交叉熵**完全相同的梯度信号**，且该等价性自然延伸到拆分接口。
- **有限缓存下的近似误差**：实际中缓存仅含部分词汇。梯度间隙可分解为**重归一化误差**（缓存内 token 概率被重新归一化）与**缺失负样本误差**（缓存外 token 贡献被忽略）。当缓存包含主要竞争 token 时，A-Loss 是标准交叉熵的良好近似。

### 2.4 One-shot SFT：面向不稳定边缘环境的单次上传模式

- L-shaped 的单向结构使客户端可完全离线训练：
  1. **单次前向传播**：客户端对本地数据集各样本计算 `(激活, 目标嵌入)` 对，存入本地缓冲区。
  2. **一次性传输**：客户端将所有缓冲对**一次上传**至服务器后即可离线。
  3. **服务器缓存与离线训练**：服务器缓存全部上传对，多次迭代更新参数，无需客户端进一步参与。
- 这使客户端角色从“永远在线的参与者”转变为“瞬态数据提供者”，通信模式从重复的逐轮交互压缩为**单一上传窗口**。

## 6. 主要结论与发现

- **L-shaped SFT 大幅降低成本且保持性能**：相比 U-shaped，通信成本在 MMLU 全量微调中降低 25%–66%，LoRA 微调中最高降低 78%（Llama3.2-1B/3B）；端到端时延缩减 26%–89%；同时微调后性能高度接近 U-shaped（如在 Llama3.2-1B MMLU 上甚至略优）。
- **One-shot SFT 进一步压缩客户端代价**：相比 U-shaped，整体通信成本降至 0.98–1.15 GB（缩减超过 80%），端到端时延降至约 45–49 分钟（缩减约 82–87%），客户端活跃时间从占训练期 95–96% 降至 11–13%。
- **单向结构带来额外效率增长**：随着本地数据遍历次数增加，L-shaped 的通信缩减持续上升（目标嵌入只需传输一次）；one-shot SFT 则保持最大缩减。
- **温度 $\tau = 1$ 是最优选择**：过小导致对比分布过尖锐、训练不稳定；过大则监督信号区分度下降。
- **One-shot SFT 对客户端退出最鲁棒**：只要客户端成功上传一次，后续断连影响很小；U-shaped SFT 则严重依赖逐轮交互，性能大幅下降。

## 7. 方法亮点

- **设计巧妙**：利用 LLM 权重绑定的固有属性，将 U-shaped 双向通信循环转化为单向数据流——无需改动模型架构，仅通过重新设计监督位置与损失函数实现。
- **理论与实证结合**：提供了严格的梯度一致性定理（理想情况下与交叉熵梯度完全一致），赋予该方案理论正当性，而非纯粹的启发式设计。
- **隐私友好性**：原始目标 token 不出设备；论文还提出了客户端私有可逆变换的保护选项（客户端本地施加私有变换矩阵 A，服务器无法直接恢复嵌入/token）。
- **真实系统实现**：在真实异构边缘设备（手机、Jetson 开发板）上完成端到端部署，而非单纯模拟，通信成本用 Wireshark 实测，具有较强说服力。
- **One-shot 理念创新**：将客户端从“全程参与者”转变为“一次性数据提供者”，从根本上回应了移动/边缘环境中连接不稳定的痛点。
- **与现有方法正交**：L-shaped 仅改变拆分训练框架本身，可与 SplitLoRA、个性化 FL 等附加优化模块组合使用。

## 8. 不足与局限

- **隐私保护尚不完善**：作者坦诚“未解决上传激活的潜在隐私泄露问题”，虽提及目标嵌入隐私风险及 DP/HE 等正交保护手段，但在联邦微调中激活本身可携带用户信息，需更深入分析。
- **任务覆盖有限**：仅在 WikiText-2（语言建模）和 MMLU（知识问答）上验证，未涉及指令微调、对话生成、代码生成等更贴近实际 LLM 定制需求的任务。
- **客户端规模较小**：实验仅含 5 个客户端，实际 FL 系统常见数十至数百客户端；客户端数量增加时通信模式与服务器缓存压力可能显著变化。
- **缓存近似缺乏系统敏感性分析**：理论给出了有限缓存下的梯度偏差分解，但未系统研究缓存大小对最终模型质量的实际影响。
- **未讨论目标嵌入泄露风险的具体量化**：虽然服务器不能直接获得 token ID，但攻击者（服务器）可能通过嵌入匹配或模型逆向推断 token，隐私保证边界需要更严谨刻画。
- **公平性的一种隐忧**：基线仅保留 U-shaped 管线而移除各工作中方法特定的辅助设计（如隐私保护、个性化机制），可能无法完全代表这些系统在其完整设计下的最优性能。
- **与标准 SFT 的对比缺失**：论文主要与 U-shaped SFT 对比，若标准 SFT（直接暴露目标 token 给服务器）在实际部署中可接受（如非敏感领域），其性能与通信基准也应纳入讨论，以便定位方案的适用边界。
