## 摘要
在联邦学习（FL）中，通信拓扑是一个运行时变量，而非固定的设计选择，因为链路和边缘设备在训练过程中会不断加入和退出。每轮训练中，服务器必须做出三个相互关联的决策，即通信拓扑、每客户端的资源分配以及用于合并本地更新的聚合规则。近期，智能体系统已开始将大型语言模型（LLM）引入联邦学习，但现有工作要么在设置阶段运行，要么仅处理客户端选择等单一运行时维度。我们提出FL-MAESTRO，一种多智能体编排器，通过三个专家LLM智能体（每个决策维度一个）直接做出联合的运行时联邦学习决策。协调器将它们的分析整合为单一决策，并在每轮执行前通过非LLM可行性检查进行确认。由于编排器消费服务器的预测故障列表，它会扣留其更新永远不会被聚合的客户端，从而消除了经典联邦学习在易变边缘网络中每轮浪费能量的主要来源。由于客户端状态以自然文本配置文件的形式读取，同一编排器可扩展到异构设备类别，无需为每类设备建立能量模型。在非IID CIFAR-10基准测试上，FL-MAESTRO在匹配最强能量感知基线准确率的同时，将每轮浪费的能量从超过三分之一降至接近零。代码可在 https://github.com/denoslab/FL-MAESTRO 获取。

## Abstract
In Federated Learning (FL), the communication topology is a runtime variable rather than a fixed design choice, since links and edge devices drop in and out during training. Each round, the server must commit three coupled decisions, namely the communication topology, per-client resource allocation, and the aggregation rule for combining local updates. Recent agentic systems have begun bringing large language models (LLM) into FL, but the existing line of work either operates at setup time or handles a single runtime dimension such as client selection. We propose FL-MAESTRO, a multi-agent orchestrator that makes the joint runtime FL decision directly through three specialist LLM agents, one per decision dimension. A coordinator combines their analyses into a single decision, and a non-LLM feasibility check confirms it before the round executes. Because the orchestrator consumes the server's predicted-failure list, it withholds clients whose updates would never be aggregated, which removes the dominant source of wasted round energy in classical FL on volatile edge networks. Because client state is read as natural-text profiles, the same orchestrator extends to heterogeneous device classes without per-class energy models. On a non-IID CIFAR-10 benchmark, FL-MAESTRO matches the accuracy of the strongest energy-aware baseline while cutting wasted round energy from over a third to near zero. Code is available at https://github.com/denoslab/FL-MAESTRO.

### 1. 核心问题与研究动机

联邦学习（FL）在真实边缘网络中面临一个根本性挑战：通信拓扑是运行时变量，而非固定的设计选择。每轮训练中，服务器必须同时提交三个紧密耦合的决策：

- **通信拓扑（τ）**：星型、层次型、环形或点对点
- **每客户端资源分配（{ri}）**：本地训练轮数、带宽分配、压缩比
- **聚合规则（σ）**：如何组合本地更新

这些决策具有深层耦合关系：拓扑决定通信成本，通信成本影响客户端的能量消耗，能量消耗决定客户端能否存活到聚合完成；而聚合规则决定了不同客户端的贡献权重，影响资源分配的激励结构。

**核心痛点**：传统FL方法（如FedAvg、FedProx、FedNova）通过固定两个维度来回避这一耦合问题——它们假定星型拓扑、统一训练轮数，仅适配聚合权重。资源感知方法（如Oort、FedLE）同样继承固定拓扑。结果导致一个核心运营症状：**边界电量客户端被纳入训练轮，耗尽能量完成本地训练和上传，却在更新被聚合前掉线，导致大量轮次能量被浪费**。

此外，现有LLM智能体在FL中的应用存在两个关键缺口：
1. 要么在系统设计/设置阶段工作（如Helmsman），要么只处理单一运行时维度（如T-ELLM只做客户端选择）
2. 均未验证开源权重、本地托管LLM的可行性，存在云依赖问题

### 2. 方法论：FL-MAESTRO框架

#### 核心思想
使用三个专家LLM智能体，每个专门负责一个决策维度，通过结构化协作协议实现联合决策。关键洞察是：**客户端状态以自然文本配置文件读取**，因此框架无需为每类设备建模，天然支持异构设备；同时**消费服务器预测的故障列表**，主动剔除会在轮中失败且更新永远不会被聚合的客户端。

#### 系统架构

```
┌─────────────────────────────────────────────────┐
│              FL-MAESTRO Orchestrator             │
├─────────────────────────────────────────────────┤
│  TopologyAgent → 提出拓扑类型与配置               │
│  AggregationAgent → 选择聚合方案与权重            │
│  ResourceAgent → 提出每客户端训练资源分配          │
│         ↓ 各自查询域工具                         │
│  Coordinator (LLM) → 综合三方分析为单一决策        │
│         ↓                                       │
│  Validator (非LLM) → 可行性检查 + 修复            │
└─────────────────────────────────────────────────┘
```

#### 关键技术细节

- **客户端配置文件**：pi = (bi, μi, βi, di, ℓi, ai)，包含剩余电量、计算能力、带宽、数据量、标签分布和聚合能力。

- **预测故障列表**：
  F(r) = {i : Ei(τdefault, rdefault) > bi}
  以FedAvg类基线采用的默认工作负载计算，精确标记在未修改FedAvg下会在轮中失败的客户端。FL-MAESTRO不会将这些客户端纳入训练。

- **能量模型**：每客户端每轮能量 = 计算项 + 通信项：
  Ei(τ, ri) = (ei·Ebase/μi) + (Pradio · CommCosti(τ, γi) / βialloc)
  能量以满电池的百分比表示，与归一化电池状态直接比较。

- **通信成本模型**：四种拓扑各有明确公式，考虑模型大小M、压缩比γ、聚合器数量A和传播邻居数k，并对称计算上下行。

- **协作协议（算法1）**：
  1. 三个智能体从FL状态生成初始提案
  2. 最多 Dmax−1 轮修订：每个智能体在查看其他两维度的提案后修改自身提议
  3. 当所有提案拓扑达成一致时提前退出
  4. 协调器综合最终决策为 (C+, τ, {ri}, σ) 的JSON
  5. 非LLM验证器强制可行约束（能量可行性、聚合器能力、权重归一化、训练轮数范围）

### 6. 主要结论与发现

1. **FL-MAESTRO同时领先精度和能量效率**：在Extreme场景（α=0.1）下FLM-Coupled达到0.615最佳精度，同时仅浪费0.2%轮次能量；而FedAvg浪费42.6%且精度仅0.581。

2. **预测故障列表机制是核心驱动力**：通过消费F(r)并剔除边界电池客户端，将浪费能量从三分之一以上降至近零——这是最核心的机制性发现。

3. **独立变体构成零浪费边界**：FLM-Independent达到精确零浪费和零失败，以小幅精度代价（约0.5-1.5%）换取了极致的能量效率，是效率偏好的Pareto点。

4. **轻量级协调足够**：添加多阈值故障探测（+A）或条件协商轮（+B）无显著精度增益，支持"最小实例化"假设——因为任务结构（类型化JSON、外部验证器、工具供给具体成本）已经消除了大部分不确定性。

5. **开源模型可达到云端性能**：Qwen3.5-35b在跨后端复现中保持与GPT-4.1-mini定性一致，验证了数据驻留约束下的自托管可行性。

6. **每轮编排平均2.0分析轮收敛**，全部服务端运行，无客户端额外开销。

### 7. 优点

- **问题定义精准**：清晰刻画了拓扑-资源-聚合的三维耦合结构，竞争动机充分（预测故障浪费能量），这是对FL运行时控制问题的正确抽象。

- **架构优雅**：三专家+协调器+非LLM验证器的分工明确。验证器提供硬约束保证，LLM只负责开放性的推理判断，避免LLM幻觉导致运行崩溃。

- **机制创新**：预测故障列表的构造方式巧妙——以FedAvg默认负载计算来界定"基线会失败"的集合，使与F-unaware基线的比较有明确定义。

- **消融设计有层次**：从单智能体到独立多智能体到耦合多智能体到增强版，逐步隔离变量，回答了"需要多少智能体协调"的开放问题。

- **诚实披露**：作者坦白指出N=3统计功效限制、t检验不显著、异质设备部署未经实测（仅为架构论证），这在论文中相当难得。

- **后勤考量周详**：报告了USD/run成本、每轮wall-clock、开源模型复现，工程价值较高。

### 8. 不足与局限

- **规模扩展性存疑**：30客户端仿真规模小，数千客户端时提示上下文预算可能直接限制应用，作者承认需要分层分解但未提出方案。

- **带宽模型过度简化**：将带宽建模为每客户端标量βi，将移动性、信道质量波动、切换、多用户干扰、OFDMA调度、重传能量全部抽象或忽略。现实网络环境远比此复杂。

- **设备异构性未经实证**：自然文本读取设备配置文件的设计优势——跨设备类别工作——仅作为架构论证而非测量结果。尚无实验证明同一编排器在不同数据格式的设备混合下的实际表现。

- **精度增益统计不显著**：FLM-Coupled在Extreme场景的精度优势通过N=3的配对单侧t检验未达显著性（p=0.39），只能主张"方向性一致"。

- **实验基准过窄**：仅CIFAR-10一个数据集、CNN一类模型。未涵盖语言任务（如Tiny Shakespeare）、推荐系统、更大的图像数据集或真实网络模拟器（如NS-3）。

- **能量模型本身未被验证**：能量计算是基于公式的仿真而非硬件实测，Ebase和Pradio等常数缺乏实测支撑。

- **LLM输出的可解释性有限**：尽管有工具和验证器支撑，但LLM推理的具体内在机制仍然不透明，难以提供可迁移的规则化知识。

- **协作协议效率**：109次LLM调用/轮，虽然成本绝对值低（$0.28/run），但在大规模部署时API成本可能积累为实质开销。
