## 摘要
图神经网络（GNN）广泛应用于自然科学、社交网络分析、芯片设计和推荐系统等领域。然而，随着图规模的增大，在单节点CPU-GPU系统上完全存储和处理图变得愈发不切实际。一种有前景的方法是将图分布到多个远程内存节点上，但这会引入一个主要瓶颈：训练期间的节点间网络拥塞。为解决这一问题，我们提出了LGNNIC，一种新颖的节点间系统架构，利用与远程内存节点共置的SmartNIC（现代系统中已有的配置）来减少分布式GNN训练中的通信开销。LGNNIC将关键预处理任务卸载到SmartNIC上，从而减少传输到计算（训练）节点的数据量，并缓解网络拥塞。我们引入了两种在预处理阶段于SmartNIC上执行的互补技术：邻居采样（Neighbor Sampling），用于执行小批量采样；以及采样批量的量化（Quantization）。为了在不同通信基础设施下评估LGNNIC，我们设计了两种机制：一种优化的低开销基于DMA的同步机制，以及一种作为基准的高开销基于套接字的替代方案。我们使用一个概念验证（PoC）系统评估了核心SmartNIC卸载机制，该系统包含一个配备NVIDIA BlueField-2 SmartNIC的远程内存节点和一个配备A100 GPU的计算节点，覆盖标准GNN工作负载和采样超参数。在大多数配置中，远程节点上的邻居采样和量化均实现了显著的训练加速。通过减少数据事务时间，邻居采样在使用Sockets和DOCA-DMA时分别实现了高达62.4倍和17.5倍的加速。量化通过减少数据传输，额外提供了分别高达3.6倍和1.3倍的加速。

## Abstract
Graph Neural Networks (GNNs) are widely used across domains such as natural sciences, social network analysis, chip design, and recommendation systems. However, as graph sizes grow, storing and processing them entirely on a single-node CPU-GPU system becomes increasingly impractical. A promising approach is to distribute the graph across multiple remote memory nodes, though this introduces a major bottleneck: inter-node network congestion during training. To address this, we propose LGNNIC, a novel inter-node system architecture that leverages SmartNICs co-located with remote memory nodes-a configuration already available in modern systems-to reduce communication overhead in distributed GNN training. LGNNIC offloads key preprocessing tasks to SmartNICs, reducing the volume of data transferred to computational (training) nodes and alleviating network congestion. We introduce two complementary techniques executed on the SmartNICs during the preprocessing phase: Neighbor Sampling, which performs mini-batch sampling, and Quantization of the sampled batches. To evaluate LGNNIC under different communication infrastructures, we designed both an optimized low-overhead DMA-based synchronization mechanism and a high-overhead socket-based alternative used as a benchmark. We evaluate the core SmartNIC offloading mechanisms across standard GNN workloads and sampling hyperparameters using a proof-of-concept (PoC) system comprising one remote-memory node with an NVIDIA BlueField-2 SmartNIC and one compute node with an A100 GPU. Both Neighbor Sampling and Quantization on the remote node demonstrated substantial training speedups in most configurations. Neighbor Sampling achieved up to 62.4x and 17.5x speedups with Sockets and DOCA-DMA, respectively, primarily due to reduced data transaction time. Quantization provided additional speedups of up to 3.6x and 1.3x, respectively, by reducing data transfer.

- **研究目标**：设计一种能缓解分布式GNN训练中网络拥塞、减少数据迁移量的系统架构，同时尽量利用现代数据中心已有的硬件配置（SmartNIC与远程内存共置），避免额外硬件成本。
- **整体含义**：论文提出LGNNIC，通过将**邻居采样（Neighbor Sampling）**和**张量量化（Quantization）**这两种原本在计算节点CPU上执行的预处理任务，卸载到远程内存节点侧的SmartNIC上执行，从而在数据传输前压缩数据量，显著降低网络传输压力，加速大规模GNN训练。

## 2. 论文提出的方法论

### 核心思想
利用SmartNIC（NVIDIA BlueField-2）作为“近数据计算”引擎，在远程内存节点侧完成部分GNN训练的数据预处理工作，减少经过网络传输的字节数，同时保持训练精度基本不变。

### 关键技术细节

1. **邻居采样卸载（Neighbor Sampling Offloading）**
   - 采用GraphSAGE风格的随机邻居采样算法，限制每个节点在图卷积层中的邻居数量，从而缩小mini-batch对应计算图的大小。
   - 采样操作完全在BlueField-2 SmartNIC上执行，而非在计算节点的CPU或GPU上执行。
   - 通过将图数据存放在SmartNIC的DRAM中，采样后只需传输紧凑的子图（节点特征、标签、邻接矩阵），大幅降低待传输数据量。

2. **张量量化（Tensor Quantization）**
   - 在SmartNIC上将mini-batch的特征张量从FP32转换为FP16，然后通过网络传输。
   - 计算节点收到后反量化回FP32再进行训练。
   - 由于特征张量往往是传输数据中的最大部分（文中指出其是主要瓶颈），量化能直接减半特征张量大小。
   - 量化全程在SmartNIC上完成，不经过远程CPU，避免额外的内存拷贝。

3. **同步机制设计**
   - **DOCA-DMA机制**（低开销、优化）：基于NVIDIA DOCA-DMA API，使用1MB固定大小缓冲区，利用ACK/头字段实现分块传输和双端同步，避免OS级网络协议栈开销，但当前并非严格零拷贝（接收端仍需一次内存拷贝）。
   - **Sockets机制**（高开销、基准）：基于以太网套接字，作为高延迟通信场景的对照基准，便于突出网络瓶颈的影响。
   - 两个机制均实现于原型系统中，并与PyG的NeighborLoader集成。

4. **算法流程（以文字说明）**
   - **远程节点（BlueField-2侧）**：初始化DOCA缓冲区和PyG数据加载器 → 遍历epoch和mini-batch → 对每个batch的元素（特征、标签、邻接张量）执行可选量化 → 转化为字节 → 按序写入DOCA缓冲区 → 等待主机ACK后发送下一块。
   - **计算节点（主机侧）**：初始化缓冲区和模型 → 等待接收新块 → 从DOCA缓冲区复制到本地聚合缓冲区 → 发送ACK → 通过PyMemoryView将缓冲区构造为张量 → 可选反量化 → 将mini-batch传输到GPU → 执行前向、损失计算、反向传播、参数更新。

## 6. 论文的主要结论与发现

1. **邻居采样卸载能带来显著加速**：
   - 与弱采样基线相比，Sockets机制下总训练时间加速比最高达62.4倍（Reddit [10,10]），DOCA-DMA下最高17.5倍（Reddit [25,10]）。
   - 数据传输时间加速比最高：Sockets下73.6倍，DOCA-DMA下5.1倍（不同数据集/配置）。
   - 采样本身在SmartNIC上比CPU慢2-10倍，但由于传输数据量大幅减少，综合训练时间仍显著缩短。

2. **量化进一步降低传输开销**：
   - 在相同采样配置下，FP16相比FP32可减少约一半特征张量大小，传输时间加速比最高达3.65倍（Sockets，Reddit [-1]），总训练时间加速比最高3.56倍；DOCA-DMA下传输加速比最高2.02倍，总训练加速比最高1.31倍。
   - 量化对测试准确率影响很小（多数配置下变化<1%，部分甚至略有提升）。

3. **DOCA-DMA机制优于Sockets**：整体绝对时间更低，但相对加速比小于Sockets，因为低开销通信下采样和预处理的相对成本更高。

4. **瓶颈转移现象**：当通信开销被DOCA-DMA压低后，预处理（采样）成为新瓶颈，需要更强的SmartNIC或进一步优化采样算法。

5. **SmartNIC是执行预处理的合适位置**：因为它位于数据到网络的路径上，能避免额外的数据拷贝，且量化等操作轻量、适合卸载。

## 7. 优点

- **新颖的系统架构思路**：将非传统的、计算密集的邻居采样卸载到SmartNIC，而非仅限简单过滤或状态无关操作，探索了SmartNIC在数据路径智能化方面的潜力。
- **双管齐下的优化策略**：采样和量化互补，一个减少图结构数据量，一个减少特征数据量，共同缓解通信压力。
- **扎实的工程实现**：实现了基于DOCA-DMA的低开销同步机制，并在学术框架PyG中集成，提供了算法伪代码，可复现性强。
- **公平的对比分析**：同时提供了高开销（Sockets）和低开销（DOCA-DMA）两种通信机制，能区分通信开销对加速比的影响，也分析了不同阶段（预处理、传输、训练）的耗时变化和瓶颈转移。
- **清晰的消融分析**：分别分析采样、量化、通信机制独立影响，有助于理解各自贡献。
- **对硬件局限性的坦诚讨论**：指出BlueField-2内存不足、DOCA-DMA缓冲区1MB限制、CPU亲和性失效等问题，并提出改进建议。

## 8. 不足与局限

- **实验规模有限**：仅验证单节点对（一个远程节点、一个计算节点），未实现真正的多节点分布系统，缺乏跨分区采样、多节点同步、真实网络（如InfiniBand）下的可扩展性验证。
- **硬件限制导致的实验缺口**：
  - SmartNIC上无法运行多worker采样（内存耗尽），因此未充分挖掘其并行潜力。
  - Reddit的基线采样配置被迫使用[-1,256]而非完全无采样，影响加速比可比性。
- **数据集代表性有限**：所选数据集虽常用但规模中等，对于更大规模图（如OGB-LSC）的适用性尚需验证。
- **量化策略简单**：仅对特征张量做FP32→FP16，未尝试更低位宽、其他张量量化或自适应量化，也未讨论量化对梯度或中间激活的影响。
- **未报告训练收敛细节**：虽然报告了测试准确率，但未说明训练达到收敛所需的epoch数量或时间，也未与现有最优系统（如DGL、Farview、SmartSAGE）进行端到端对比。
- **零拷贝仍有差距**：当前DOCA-DMA实现因缓冲区限制存在一次额外内存拷贝，并非最优实现，可能低估了性能上限。
- **未来工作依赖性强**：多节点扩展、DOCA-RDMA、BlueField-3/4等改进均未完成，当前结论局限于PoC环境。
