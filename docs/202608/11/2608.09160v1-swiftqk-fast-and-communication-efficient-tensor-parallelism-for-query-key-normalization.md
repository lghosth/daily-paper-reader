## 摘要
查询-键归一化（QK-Norm）提高了现代大型语言模型（LLM）的训练稳定性和质量。然而，在张量并行（TP）下，逐层的 QK-Norm 会引入额外的跨 GPU 通信，因为归一化因子依赖于完整的隐藏向量。我们提出了 SwiftQK，一个多 GPU RMSNorm 内核，它仅交换标量归一化统计量，并在无死锁的持久内核中将剩余的点对点规约与独立的逐元素计算重叠。在最新 LLM 上的评估表明，与使用全向量 All-Gather 的标准 TP QK-Norm 相比，SwiftQK 将 QK-Norm 延迟降低了 81.4% 至 93.9%。在端到端服务中，与基于 All-Gather 的基线相比，SwiftQK 平均将 TPOT 降低了 29.5%；与优化的标量聚合实现相比，平均降低了 14.3%。

## Abstract
Query-Key Normalization (QK-Norm) improves the training stability and quality of modern Large Language Models (LLMs). However, under Tensor Parallelism (TP), layerwise QK-Norm introduces additional cross-GPU communication because the normalization factor depends on the full hidden vector. We present SwiftQK, a multi-GPU RMSNorm kernel that exchanges only scalar normalization statistics and overlaps the remaining Peer-to-Peer reduction with independent element-wise computation in a deadlock-safe persistent kernel. Evaluations on recent LLMs show that SwiftQK reduces QK-Norm latency by 81.4--93.9% relative to the standard TP QK-Norm using full-vector All-Gather. In end-to-end serving, SwiftQK reduces TPOT on average by 29.5% over the All-Gather-based baseline and by 14.3% over an optimized scalar-aggregation implementation.

# 论文总结：SwiftQK: Fast and Communication-Efficient Tensor Parallelism for Query-Key Normalization

## 1. 核心问题与整体含义

- **背景**：Query-Key Normalization（QK-Norm）被现代 LLM 广泛采用，用于提升注意力训练稳定性与最终质量。其逐层（layerwise）形式需要对完整的 Q 或 K 隐藏向量计算归一化因子。
- **问题**：在张量并行（Tensor Parallelism, TP）下，Q/K 隐藏维度被切分到多个 GPU。计算 RMSNorm 的归一化因子需要全局平方和，因此每个 GPU 无法仅凭本地分片完成，必须引入额外的跨 GPU 通信（通常为 All-Gather）。
- **影响**：QK-Norm 这一看似轻量的操作，打破了 TP 原本“计算本地化、通信只在层间”的高效模式，成为显著瓶颈。论文实测表明：在 OLMo2/OLMo3 上，4 GPU TP 相比 PP 的延迟优势从无 QK-Norm 模型的 36.2% 缩小到 7.5% 和 12.0%，且 QK-Norm 开销随 TP 规模增大而上升。
- **意义**：SwiftQK 从“通信量缩减 + 通信计算重叠”两个层面，解决了 TP 下 QK-Norm 的通信主导瓶颈，为现代 LLM 推理的高效张量并行提供了关键优化。

## 2. 方法论

SwiftQK 是一个多 GPU 融合 RMSNorm 内核，核心设计如下：

- **总体思想**：将完整 Q/K 激活交换替换为仅交换标量统计量（局部平方和），并通过持久内核将点对点（P2P）标量规约与独立的逐元素计算重叠，从而在保持归一化语义不变的前提下大幅降低通信开销。
- **算法三阶段**：
  - **阶段 A：局部聚合**
    - 每个 GPU 先在本地分片上计算平方和 \( S_{local} = \sum x_j^2 \)。
    - 计算结果写入 IPC 缓冲区中的对应槽位，等待跨 GPU 规约。
    - 通信量由 O(H)（全向量）降为 O(1)（标量）。
  - **阶段 B：通信-计算重叠**
    - Warp 0 专门负责通信路径：向对端 GPU 发送远程标志，自旋等待本地标志，然后从所有 IPC 缓冲区读取平方和并累加得到全局 \( S_{global} = \sum_{k=0}^{N-1} S^{(k)}_{local} \)。
    - 其余 warp 同时执行与归一化因子无关的逐元素权重乘法 \( x_j \times \gamma_j \)。
    - 通过将 P2P 规约延迟隐藏在权重乘法之后，减少同步等待暴露。
  - **阶段 C：最终归一化**
    - 使用全局 RMS 因子 \( \text{RMS}^{-1} = 1/\sqrt{S_{global}/H + \epsilon} \) 对已乘权重的本地分片进行缩放，写出归一化结果。
- **死锁安全机制**：
  - 采用持久执行模型，启动的线程块数不超过 `Bres × NSM`（每 SM 可常驻块数 × SM 数），确保参与同步的 peer block 同时驻留，避免循环等待。
  - 当 token 数大于常驻块数时，每个块按步长循环处理多个 token，形成块级 token 流水线，兼顾吞吐和安全性。
- **数值精度**：局部平方和与跨 GPU 标量聚合均使用 FP32 累加，即使输入为 BF16 或 FP8，也能保持与参考路径一致的精度。

## 7. 优点

- **通信量最小化**：将全向量交换缩减为标量平方和聚合，从根源上减少跨 GPU 数据量。
- **通信计算重叠**：在统一内核中利用不同 warp 分工，将 P2P 规约延迟隐藏在独立的权重乘法之后，进一步提升端到端性能。
- **死锁安全的持久内核**：通过有界网格和常驻块机制，既保证同步安全，又避免频繁内核启动开销。
- **语义保持**：不改变 RMSNorm 的数学定义，仅改变实现路径，易于集成。
- **精度稳健**：FP32 累加有效防止低精度输入下的误差累积。
- **问题定位精准**：明确指出“仅是通信计算重叠”不足以解决 QK-Norm 瓶颈，必须结合通信量缩减，思路清晰。
