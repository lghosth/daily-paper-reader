## 摘要
MPI_Allreduce是大型科学计算和分布式机器学习中性能最关键的集合操作之一，然而中小消息场景仍然具有挑战性：延迟、同步深度以及域内与域间通信之间的强硬件层次结构都增加了每次调用的成本。我们提出了CHIARA，一种可配置的层次化Allreduce，它通过逻辑批处理车道拓扑编码硬件层次结构，并执行分阶段调度，其中每次只有缩减向量的有界部分处于活动状态。批间通信通过旋转根车道原语分布在多个秩之间，避免了集中式领导者。该工具还通过保留Reduce-Scatter/Allgather边界上的车道对齐中间布局，实现了半组合的Rabenseifner风格Allreduce，从而消除了冗余的域内重组。我们在Polaris、Aurora和Fugaku上评估了该工具，与供应商MPI_Allreduce相比，实现了高达1.94倍、13.43倍和13.48倍的加速，在并行k-means应用中实现了高达2.2倍的端到端加速。

## Abstract
MPI_Allreduce is among the most performance-critical collectives in large-scale scientific computing and distributed machine learning, yet the small- and medium-message regime remains challenging: latency, synchronization depth, and strong hardware hierarchy between intra- and inter-domain communication all compound per-invocation cost. We present CHIARA, a configurable hierarchical Allreduce that encodes hardware hierarchy through a logical batch-lane topology and executes a staged schedule in which only a bounded portion of the reduction vector is active at a time. Inter-batch communication is distributed across multiple ranks via a rotating-root lane primitive, avoiding centralized leaders. Tool further enables a semi-composed Rabenseifner-style Allreduce by preserving a lane-aligned intermediate layout across the Reduce-Scatter/Allgather boundary, eliminating redundant intra-domain reorganization. We evaluate Tool on Polaris, Aurora, and Fugaku, achieving speedups of up to 1.94x, 13.43x, and 13.48x over vendor MPI_Allreduce, and up to 2.2x end-to-end speedup in a parallel k-means application.

- 为此提出 **CHIARA（Configurable Hierarchical Allreduce Algorithm）**，一种可配置、层次化、分布式的 Allreduce 算法，使层次结构显式化、可调参数化，并消除阶段间冗余操作。

## 2. 论文提出的方法论

### 2.1 核心思想
- 基于 Rabenseifner 的 Reduce-Scatter + Allgather 分解结构，但重新设计为层次化、可配置形式。
- 三个关键洞察：
  1. 用 **batch–lane 拓扑** 编码硬件层次：rank 被划分为若干 batch（局部域），同一 batch 内的 rank 位于同一快速通信域；不同 batch 中相同位置的 rank 形成 lane，用于跨 batch 通信。
  2. **分阶段调度**：每次只处理缩减向量的一部分，限制工作集，减少全局同步深度，并保持负载均衡。
  3. **半组合设计**：在 Reduce-Scatter 和 Allgather 之间保留 lane 对齐的中间布局，消除边界处冗余的域内重组。

### 2.2 关键技术细节
- **Batch–lane 拓扑**：
  - 总 rank 数 \(P\)，batch 大小 \(b\)，batch 数 \(B = P / b\)。
  - rank \(r = xb + i\)，其中 \(x\) 为 batch id，\(i\) 为 lane id。
  - \(b \le PPN\)（每节点 rank 数），保证 batch 内通信尽量在快速域内。
- **分阶段执行**：
  - 每个 rank 将输入向量划分为 \(B\) 个 block。
  - 阶段数 \(I = \lceil B/b \rceil = \lceil P/b^2 \rceil\)。
  - 阶段 \(t\) 中，lane \(i\) 处理 block \(d = t \cdot b + i\)，使多个 lane 并行处理不同块。
- **可调参数**：
  - batch size \(b\)：控制层次粒度，平衡域内通信与跨域阶段数。
  - 独立 radix \(k_{RS}\) 和 \(k_{AG}\)：分别控制 Reduce-Scatter 与 Allgather 阶段内部递归交换的扇出，分别调节通信深度与每轮开销。

### 2.3 算法流程（文字说明）
- **层级 Reduce-Scatter**：
  - Phase I：batch 内 radix-\(k_{RS}\) 递归交换进行局部归约，产生 lane 对齐的部分结果。
  - Phase II：通过 **LaneOp（REDUCE 模式）** 进行跨 batch 归约，根 batch 由旋转根公式 \(\rho = tb + i\) 确定，避免固定领导者。
  - Phase III：在 batch 内重新分配归约结果（但半组合设计可跳过此步）。
- **层级 Allgather**：
  - Phase I：batch 内 lane 对齐（半组合设计可跳过）。
  - Phase II：通过 **LaneOp（BCAST 模式）** 沿 lane 执行跨 batch 广播。
  - Phase III：batch 内 radix-\(k_{AG}\) 递归交换完成复制。
- **半组合 Allreduce**：
  - 四阶段：batch 内 Reduce-Scatter → 跨 batch lane reduction → 跨 batch lane broadcast → batch 内 Allgather。
  - 由于中间结果保持 lane 对齐，无需在 Reduce-Scatter 末端和 Allgather 起始端进行额外重组，减少同步和数据移动。

- **可配置性**：显式暴露 batch size 和双 radix 参数，可针对不同平台/消息大小调优，优于固定分层实现。

- **端到端应用收益**：不仅微基准提升，还展示了 k-means 中的实际加速，证明实用价值。
